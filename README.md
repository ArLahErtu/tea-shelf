# Чайная полка ☕ — личный учёт чая

Веб-сервис личного учёта чая: остатки, журнал завариваний с оценками,
список покупок, общий каталог чаёв и заявки «на модерации».
Дальше — ИИ-ассистент подбора (этап 3).

## Что умеет (MVP, недели 1–2)

- Вход/регистрация (Supabase Auth), данные только свои (RLS).
- Личная полка: остатки (г/пакетики/упаковки), статусы «Мало/Закончился»,
  список «Что докупить» с дозакупкой одной кнопкой, хотелки.
- Журнал завариваний: количество, оценка ★, заметка; атомарное списание
  через RPC `brew_tea` (+ счётчик популярности в каталоге).
- Общий каталог: поиск, сортировки, карточка чая, «На полку» с выбором
  количества, заявки на модерацию (видны только автору до одобрения).

## Стек

- Статический фронтенд: HTML + CSS (модульный: base/components/pages) + ES-модули JS.
- Supabase: Postgres + Auth + RLS + RPC. Без собственного бэкенда.

## Структура

- `index.html / catalog.html / shelf.html` — страницы;
- `main.js / catalog.js / shelf.js` — логика страниц;
- `common.js, auth.js, supabaseClient.js, config.js, ui.js,
   teaModal.js, amountModal.js, chatbot.js` — общие модули;
- `base.css, components.css, index.css, catalog.css, shelf.css,
   chatbot.css` — стили (`styles.css` — легаси главной, будет убран позже);
- `config.js` — URL и anon-ключ Supabase (anon-ключ публичен по модели
  Supabase; безопасность обеспечивается RLS, а не секретностью ключа).

## Локальный запуск

1. Любым статическим сервером, например: `npx serve` или Live Server в VS Code.
2. Ключи Supabase уже в `config.js`; для своего проекта — заменить
   `SUPABASE_URL` / `SUPABASE_ANON_KEY` (Dashboard → Settings → API).
3. Схема БД: таблицы `tea_catalog`, `user_shelf`, `brew_journal`, `wishlist`;
   ограничения и RPC применены SQL-блоками (unique `(user_id, tea_id)`,
   функция `brew_tea`, RLS-политики).

Тестовые аккаунты: `kirill@example.com / demo123`,
`anya@example.com / demo123`, `maksim@example.com / demo123`
(отключаются флагом `SHOW_DEMO_ACCOUNTS` в `config.js`).

## Деплой

Статика без сборки: репозиторий импортируется в Vercel/Netlify
с пресетом «Other», publish-каталог — корень репозитория.
